# Adjuntos de accidentes y capacitaciones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subir, listar, descargar y borrar archivos ligados a cada accidente y capacitación y a su colaborador, sobre Firebase Storage.

**Architecture:** Dominio puro (validación, rutas) y orquestación pura con puertos inyectados; infraestructura delgada (Storage + colección `adjuntos`); un componente `Adjuntos` reutilizable. Lecturas por el almacén compartido existente.

**Tech Stack:** Next.js 14, React 18, TypeScript, Firebase JS SDK (`firebase/storage`, ya incluido en el paquete `firebase`), Vitest, pnpm 11.

**Spec:** `docs/superpowers/specs/2026-10-01-adjuntos-design.md`

## Global Constraints

- Tipos permitidos: PDF, JPG, PNG, WebP, doc, docx, xls, xlsx. Máximo 10 MB por archivo (`10 * 1024 * 1024`), 10 archivos por registro, 3 subidas simultáneas.
- Ruta: `adjuntos/{colaborador_id}/{modulo}/{registro_id}/{archivo_id}`; `modulo` es `accidentes` o `capacitaciones`; el nombre original nunca va en la ruta.
- Documento `adjuntos`: `colaborador_id, modulo, registro_id, archivo_id, nombre, tipo, tamano, subido_por, subido_en`; los cuatro primeros son inmutables.
- Roles: admin y capturista suben y borran; consulta solo lee y descarga.
- Descarga: `getDownloadURL` en el cliente al hacer clic (token sin vencimiento, riesgo aceptado); sin servidor. Antes se usó URL firmada de servidor (commit 52a8bbd) y se retiró.
- Cero valores reales en el repo (bucket, proyecto, dominio): todo por variables de entorno y plantillas; nunca leer ni editar `.env.local` ni `.valores-sensibles.local`; el valor del bucket lo pone el usuario en `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`. Región `us-east1` solo en documentación.
- Comentarios de una línea, sin emojis, español en la UI, archivos pequeños, TDD, pnpm. Sin nuevas dependencias.
- La variable del bucket se valida de forma perezosa (al usar Storage), para que builds y pruebas sin ella no fallen.
- Commits con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; no hacer push.

### Task 1: Dominio y orquestación puros

**Files:**
- Create: `src/domain/adjuntos.ts`, `src/domain/adjuntos.test.ts`
- Create: `src/application/adjuntos-subida.ts`, `src/application/adjuntos-subida.test.ts`

**Interfaces:**
- Produces (dominio):
  - `type ModuloAdjunto = 'accidentes' | 'capacitaciones'`
  - `interface Adjunto { id: string; colaborador_id: string; modulo: ModuloAdjunto; registro_id: string; archivo_id: string; nombre: string; tipo: string; tamano: number }`
  - `const MAX_BYTES`, `MAX_POR_REGISTRO = 10`, `CONCURRENCIA = 3`
  - `validarArchivo(a: { nombre: string; tipo: string; tamano: number }, existentes: number): string | null` (mensaje en español o null; valida extensión Y MIME contra la lista, tamaño > 0 y <= MAX_BYTES, tope por registro)
  - `rutaAdjunto(p: { colaborador_id: string; modulo: ModuloAdjunto; registro_id: string; archivo_id: string }): string`
  - `nombreSeguro(nombre: string): string` (usa `limpiarTexto` de `src/domain/texto.ts`, quita separadores de ruta, conserva extensión, máx. 120 caracteres)
  - `nuevoArchivoId(): string` (`crypto.randomUUID()` sin guiones)
- Produces (aplicación):
  - Puertos: `interface PuertoAlmacenamiento { subir(ruta: string, archivo: File, alProgreso: (frac: number) => void, senal: AbortSignal): Promise<void>; borrar(ruta: string): Promise<void> }` y `interface PuertoMetadatos { crear(a: Omit<Adjunto, 'id'>): Promise<string>; borrar(id: string): Promise<void> }`
  - `type EstadoSubida = 'pendiente' | 'subiendo' | 'listo' | 'error' | 'cancelado'`; `interface ItemSubida { clave: string; archivo: File; estado: EstadoSubida; progreso: number; motivo?: string }`
  - `crearSubidor(p: { almacenamiento; metadatos; destino: { colaborador_id; modulo; registro_id }; existentes: () => number; alCambiar: (items: ItemSubida[]) => void }): { agregar(archivos: File[]): void; reintentar(clave: string): void; cancelar(clave: string): void; cancelarTodo(): void }`

- [ ] **Step 1: Pruebas rojas del dominio.** Casos: acepta PDF/JPG/PNG/WebP/docx/xlsx válidos; rechaza `.exe`, MIME que no corresponde a la extensión, 0 bytes, 10 MB + 1, y el undécimo archivo (`existentes = 10`); `rutaAdjunto` sin nombre original; `nombreSeguro('..\\a/b  Informe.PDF')` no contiene separadores y conserva `.pdf`/`.PDF`; `nuevoArchivoId` produce 32 hex distintos.
- [ ] **Step 2: Ejecutar `pnpm vitest run src/domain/adjuntos.test.ts`; debe fallar.**
- [ ] **Step 3: Implementar `adjuntos.ts` mínimo; debe pasar.**
- [ ] **Step 4: Pruebas rojas del subidor** con puertos falsos: valida antes de subir y marca `error` con motivo sin llamar al puerto; nunca más de 3 subidas simultáneas; un fallo no detiene a los demás; `reintentar` repite solo ese archivo; progreso se propaga; al terminar `subir` crea metadatos y marca `listo`; si `metadatos.crear` falla se llama `almacenamiento.borrar(ruta)` y el estado es `error` (compensación); `cancelar` aborta la señal y no crea metadatos; `cancelarTodo` cancela pendientes y en curso; el tope por registro cuenta `existentes() + listos + en curso`.
- [ ] **Step 5: Implementar `adjuntos-subida.ts`; `pnpm typecheck && pnpm lint && pnpm test` en verde.**
- [ ] **Step 6: Commit** `feat(adjuntos): dominio y subidor puros con pruebas`.
